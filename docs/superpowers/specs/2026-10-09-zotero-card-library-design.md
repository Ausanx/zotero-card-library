# Zotero 卡片式文献库设计

## 目标

为 Zotero 9.0.6 增加一个独立的大窗口，将现有文献显示为 EzRead 风格的卡片瀑布流。Zotero 继续作为唯一的文献库、元数据来源和 PDF 阅读器；插件只负责浏览、封面选择、筛选、收藏、阅读状态和本地视觉整理。

卡片封面优先使用论文正文中的 Figure、照片或图表区域。候选图由 JavaScript、Zotero 内置 PDF.js 和本地规则生成，不调用大语言模型、视觉模型、远程服务或外部 AI API。用户可以从候选图中改选，也可以在 PDF 页面区域中手动框选；没有可靠内部图片时才回退到 PDF 首页。

## 非目标

- 不迁移、复制或重建 Zotero 文献库。
- 不实现翻译、论文问答、AI 摘要、模型选择或任务队列。
- 不修改 Zotero 条目字段、标签、合集、PDF、注释或笔记。
- 不替换 Zotero 的中央文献列表，也不依赖修改 Zotero 内部列表 DOM。
- 不提供 Zotero Web API、云端同步、遥测或第三方账号连接。
- 不保证扫描版 PDF 的 OCR 或复杂版式的自动 Figure 识别。

## 用户体验

### 窗口和导航

插件通过 Zotero 菜单或工具栏入口打开独立的卡片库窗口。窗口大小、位置、右侧详情抽屉宽度和上次浏览状态保存在插件本地设置中。

窗口分为三块：

1. 左侧栏：搜索、全部文献、当前合集、标签、排序入口。
2. 中央卡片区：响应式瀑布流，卡片高度随标题和图片比例变化。
3. 右侧详情抽屉：单击卡片后出现，可拖动宽度；中央区域同步变窄并重新计算列数。

初始视觉沿用 EzRead 的圆角卡片、柔和阴影、浅色背景、彩色卡片和白色图片区域。第一版同时提供浅色和深色主题，默认使用浅色；两套主题共用布局和卡片分类语义。卡片图片使用 `contain`，不强行裁掉 Figure 的标签和边界。

### 卡片内容

卡片默认显示：

- 标题，完整换行，不强制截断；
- 作者，过长时显示前几位并保留其余人数提示；
- 期刊或出版物；
- 出版年份；
- 本地阅读状态；
- 收藏按钮；
- 更换封面按钮；
- 打开 PDF 按钮。

简记、摘要、标签、DOI、附件和普通笔记放在右侧详情抽屉，不在卡片上直接铺开。简记字段不硬编码，设置中提供字段映射；在用户确认实际字段前默认不显示简记。

单击卡片打开详情抽屉。抽屉中显示标题、作者、期刊、年份、DOI、摘要、标签、简记、附件和封面候选。打开 PDF 始终调用 Zotero 原生阅读器，保留 Zotero 的阅读位置和原有工具。

### 阅读状态和收藏

插件提供“未读、在读、已读”三种本地状态：

- 初始状态为未读；
- 从插件或 Zotero 原生 Reader 打开 PDF 后，未读自动变为在读；
- 已读由用户在详情抽屉中手动设置；
- 打开详情、查看候选图或只浏览卡片不会改变阅读状态。

Zotero 9.0.6 的 `attachmentLastRead` 作为“最近阅读”排序和刷新依据；它不被解释为阅读完成比例。

收藏、阅读状态、封面选择、颜色覆盖和布局偏好只写入插件自己的本地状态文件，不写入 Zotero 标签或条目字段。

### 颜色和排序

插件提供一组 EzRead 风格的浅金、蓝、绿、灰和中性色。颜色默认只代表视觉分类，不预设“重要”“已读”或期刊等级的含义。

用户可以为合集或标签配置颜色规则，也可以为单篇文献设置本地颜色覆盖。规则优先级为：单篇覆盖 > 标签规则 > 合集规则 > 默认色；同一层级的规则按设置中的顺序执行。

默认排序包括最近添加、最近打开、发表年份、标题和作者。搜索覆盖标题、作者、期刊、标签、摘要、普通笔记以及用户配置的简记字段；不进行 PDF 全文索引。

### 批量操作

第一版支持多选文献并批量加入 Zotero 合集。批量操作由用户明确触发，写入 Zotero 合集关系；其他卡片状态仍只写入插件本地状态。拖动卡片到合集和更复杂的批量编辑留作后续增强。

## 数据与文件边界

### Zotero 作为事实来源

插件从 Zotero API 读取父条目元数据、作者、出版物、年份、摘要、标签、合集、笔记和子附件。PDF 子附件通过 Zotero 的附件路径接口读取，支持 Zotero storage 和 linked file；找不到本地文件时卡片仍显示元数据。

插件不直接读取或写入 Zotero SQLite 数据库，不修改 Zotero 数据库表结构，不依赖 Zotero Web API。

### 插件本地状态

插件在 Zotero profile 下维护一个版本化 JSON 状态文件和缓存目录。状态结构包含：

```text
CardState {
  schemaVersion: number,
  items: {
    [itemID]: {
      favorite: boolean,
      readingStatus: "unread" | "reading" | "read",
      colorOverride: string | null,
      cover: CoverReference | null,
      updatedAt: number
    }
  },
  colorRules: ColorRule[],
  fieldMapping: { memoField: string | null },
  windowState: { x, y, width, height, detailWidth },
  viewState: { scope, query, sort, scrollTop }
}

CoverReference {
  attachmentID: number,
  source: "candidate" | "manual" | "first-page",
  page: number,
  bbox: [number, number, number, number],
  cacheKey: string
}
```

封面缓存按附件 ID、附件修改时间或内容指纹、页码和归一化矩形生成键。缓存丢失时可以重新生成，不影响 Zotero 数据。状态写入采用临时文件和原子替换，升级时按 `schemaVersion` 迁移。

“导出备份”保存状态 JSON、颜色规则、字段映射、封面引用和阅读状态；缩略图缓存可选打包，恢复时允许按引用重新生成。备份不包含 PDF 原文和 Zotero 私人数据副本。

## 封面候选算法

### 处理流程

1. 找到父条目的主 PDF；多个 PDF 时默认选择主 PDF，详情抽屉允许更换附件来源。
2. 卡片第一次进入可见区域时，把附件加入后台处理队列；窗口启动不阻塞全部文献。
3. 通过 Zotero 9.0.6 内置 PDF.js 的 `getTextContent()` 读取页面文字及坐标。
4. 识别 `Fig. 1`、`Figure 1`、中文“图 1”等图注行，并结合相邻页面图形、文字和空白区域生成候选矩形。
5. 使用本地规则评分：图注匹配、图号、页码、候选区域面积、图注与区域距离、常见主图关键词和异常大面积背景惩罚。
6. 对最高分候选和其余候选按原 PDF 页面区域重新渲染，不对已压缩缩略图二次裁剪。
7. 保存最多三个候选及其页码、图注和归一化坐标，卡片默认显示最高分候选。

规则算法不承诺所有出版物版式都能正确识别完整 Figure。复杂矢量图、多栏布局、扫描 PDF 和缺少图注的图片都可以通过候选切换或手动框选修正。候选为空时使用 PDF 首页；本地 PDF 不可用时显示占位图和附件不可用提示。

### 手动封面

详情抽屉提供“手动选择封面”：插件在自己的 PDF 页面预览中显示页码选择和矩形框选，保存页码与归一化坐标，不创建 Zotero 图片标注。重新打开时按原 PDF 区域渲染，保证清晰度和可重复生成。

## 插件架构

项目使用 Zotero 9 插件脚手架和 WebExtension-style manifest 加 bootstrapped lifecycle，第一版界面提供简体中文文案。代码按以下职责拆分：

- `src/bootstrap/`：插件生命周期、主窗口加载/卸载和菜单入口；
- `src/zotero/`：条目、合集、标签、附件和 Notifier 适配器；
- `src/data/`：本地状态、原子保存、备份与迁移；
- `src/covers/`：PDF.js 页面文字读取、候选规则、区域渲染和缓存；
- `src/window/`：独立窗口创建、恢复、关闭和消息通信；
- `src/ui/`：侧栏、卡片瀑布流、详情抽屉、候选画廊和设置；
- `src/styles/`：颜色变量、卡片表面、响应式列布局和可访问性状态；
- `tests/`：纯逻辑单元测试、PDF fixture 测试、状态迁移测试和打包检查；
- `docs/`：设计、开发、安装、隐私和开源贡献说明。

窗口 UI 与 Zotero 适配层通过明确的数据 DTO 通信。UI 不直接调用 Zotero 全局对象；这样可以在没有 Zotero 的情况下测试卡片布局、搜索、颜色规则和状态迁移。

## 开源与插件市场要求

- 默认许可证为 MIT；仓库包含完整 `LICENSE`、README、安装说明、开发说明和变更日志。
- 不收集遥测，不联网，不上传文献、PDF、笔记或封面。
- 若复制 EzRead 的实质代码或样式，保留其 MIT 版权和许可证说明，并在 `NOTICE` 中标明来源；仅借鉴设计思想时也在 README 致谢。
- 发布产物为可安装的 `.xpi`，版本号、插件 ID 和最低 Zotero 版本保持稳定。
- manifest 明确声明仅需要 Zotero 插件运行所需权限，不引入无关 WebExtension 权限。
- README 明确说明：插件拥有 Zotero 插件的本地访问能力，状态文件位置、备份方式、PDF 不可用时的行为和卸载后的数据清理方式。
- 首版目标为 Zotero 9.0.6 及同一主版本的兼容更新；低于该版本的 Zotero 不在支持范围内。

## 验证标准

### 逻辑验证

- 纯逻辑测试覆盖标题、作者、期刊、年份和可配置简记字段映射。
- 颜色规则按单篇覆盖、标签、合集、默认色的优先级返回确定结果。
- 搜索覆盖标题、作者、期刊、标签、摘要、普通笔记和映射后的简记。
- 本地状态的原子写入、损坏恢复、版本迁移和备份导入导出有测试。
- Figure 候选评分对英文图注、中文图注、无图注和多栏页面有固定 PDF fixture 测试。

### Zotero 验证

- 使用独立 Zotero 9.0.6 测试 profile 安装 `.xpi`。
- 从菜单打开和关闭独立窗口，验证重复打开不会创建重复窗口。
- 修改条目标题、标签、合集和附件后，卡片自动刷新。
- 从卡片和 Zotero 原生 Reader 打开 PDF，验证在读状态和最近阅读排序刷新。
- 逐一验证有 Figure、只有首页图片、多个 PDF、linked file、文件缺失和扫描 PDF。
- 验证批量加入合集只改变 Zotero 合集关系，收藏、颜色和阅读状态不写入条目。
- 在低宽度窗口、详情抽屉拖动、不同 DPI 和较长标题/简记下检查瀑布流不溢出。

### 发布验收

- 可从干净 Zotero 9.0.6 profile 安装、使用、导出备份、卸载和重新安装。
- 无网络时卡片浏览、候选缓存、详情和 PDF 打开不依赖远程服务。
- 构建产物包含 LICENSE、NOTICE、README、版本号和可追溯源码提交。
- 现有 Zotero 文献和附件在插件卸载后仍可正常使用。
